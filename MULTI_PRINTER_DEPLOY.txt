MULTI-PRINTER MERGE: GITHUB + RENDER

FILES
- app_multi_printer.py: replace the repository app.py with this file (rename to app.py).
- HP_Print_Bridge_Agent_Merged.zip: install on PC 192.168.1.9.

RENDER
1. In Render service Environment, add PRINT_BRIDGE_KEY with a strong secret value.
2. Save/redeploy after pushing the updated app.py to GitHub.
3. If Render uses a persistent disk/database, the new printer columns migrate automatically.
4. If the SQLite database is not persistent, queued jobs can disappear after restart.

EXISTING EPSON BRIDGE
No change is required if it calls /api/print-jobs/next without a printer_id.
The server treats a missing printer_id as epson, so it can claim only EPSON jobs.

HP BRIDGE
1. Extract on 192.168.1.9.
2. Run INSTALL.bat.
3. Set config.json server_url to the exact Render public URL (no trailing slash).
4. Set bridge_key to the same PRINT_BRIDGE_KEY configured in Render.
5. Run TEST_CONFIG.bat and then START_HP_BRIDGE.bat.
6. HP agent calls /api/print-jobs/next?printer_id=hp_135w and cannot take EPSON jobs.

PORTAL
When PRINT THIS PRICE is selected, the portal asks:
1 = EPSON
2 = HP Laser MFP 131 133 135-138
The selected printer is stored with the job and routed to only that bridge.
